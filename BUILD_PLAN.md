# Ops Trust Tai Build Plan

## Phase 1

Goal: prove the product shape with a runnable front-end scaffold.

Deliver:

- TrustTai command-center shell
- seeded WordPress projects
- project overview
- new-run intake
- active run view
- QA proof
- recommendations and memory surfaces
- local persistence

## Phase 2

Goal: replace seeded state with real backend objects.

Deliver:

- canonical schema and repository layer
- auth and roles
- Postgres/Supabase data model
- project CRUD
- run persistence
- memory persistence
- approvals and audit events

## Phase 3

Goal: wire the agent operating system into the guarded product.

Deliver:

- state-aware agent context payloads
- tool permissions by phase
- guardrail policy engine
- evidence capture
- recommendation writeback

## Phase 4

Goal: raise confidence from good internal tool to deployable operator system.

Deliver:

- richer QA flows
- rollback pathways
- production verification loops
- real approval UX
- project onboarding workflow
