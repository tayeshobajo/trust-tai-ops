# Ops Trust Tai

## Product Thesis

`ops.trust-tai.com` is the TrustTai command center for WordPress engineering work.

It is not a chatbot with access.
It is an application layer around senior technical judgment:

1. project memory
2. guarded run states
3. visible progress
4. QA proof
5. recommendations that compound

The product should make breaking a site structurally hard and make the team structurally better while using it.

## V1 Promise

Give the system access.
Confirm backup.
Assign the task.
Watch progress.
Review QA.
Leave with clarity and recommendations.

## V1 Boundary

WordPress operations only.

Focus:

- malware cleanup
- performance optimization
- plugin/theme conflict diagnosis
- broken update recovery
- hardening
- QA and post-run recommendations

Not in V1:

- general devops
- non-WordPress stacks
- open-ended agent autonomy
- billing/client portal work

## Product Spine

The product is a two-sided operating system:

- human side: clarity, trust, control
- agent side: structure, memory, boundaries

Both sides stay aligned through shared run state.

## Core Surfaces

- Projects dashboard
- Project overview
- New run intake
- Active run view
- QA proof
- Recommendations history
- Project memory

## Core Rules

- no risky action before backup confirmation
- no execution before diagnosis and plan artifacts
- no completion without QA or waiver
- no project memory crossover
- no silent risk

## Phase 1 Goal

Ship a real runnable front-end scaffold that proves the command-center shape, seeded project model, run-state UX, and TrustTai brand direction before backend wiring.
